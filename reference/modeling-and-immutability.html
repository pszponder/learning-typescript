TypeScript desk reference

Modeling and immutability

Core collections are covered in the arrays, objects, Map, and Set lessons. This sheet covers supporting type and modeling concepts. Interfaces and generics are optional later topics.

TopicWorking definition
Readonly and runtime freezingReadonly types restrict writes through a reference during checking. ReadonlyArray<T>, ReadonlyMap<K, V>, and ReadonlySet<T> expose reading operations; they do not freeze the underlying values. Another mutable alias can still change the collection. JavaScript has no built-in frozen Map or Set equivalent to Python’s frozenset. Object.freeze is shallow and freezes ordinary properties; it does not disable Map.set or Set.add.
Dictionary objects and RecordRecord<K, V> is a TypeScript utility describing object properties, not a runtime container. A finite union of keys requires each named key. An open string key type cannot guarantee every possible key exists. Use noUncheckedIndexedAccess for possibly absent dynamic entries.
Transform and search arraysmap transforms each entry; filter retains entries; find returns the first match or undefined. some asks whether any entry matches, every whether all match. These callbacks fit the arrow functions you practiced. Keep callbacks pure when deriving a view.
Classes, instances, and thisA class defines how instances are constructed and which methods they share. new creates an instance; this refers to the receiver of a method call. A class is useful when state and behavior belong together. Plain records and functions remain useful for game rules.
Interfaces and structural typingAn interface describes a shape for the checker. Structural typing means a matching shape is sufficient without explicit inheritance or implements. Interfaces disappear at runtime; they cannot validate a request. A class can declare implements to check its instance shape, but that does not generate methods.
Model distinct game statesA discriminated union combines object shapes with a shared literal-valued tag. Checking that tag narrows which fields exist. This avoids a single object with many optional fields that permits incoherent combinations.
Generics: preserve the element typeA type parameter connects the types used by a function. T stands for an element type selected or inferred for a call; it does not create a runtime type value. ReadonlyArray<T> already uses this idea. Generics preserve relationships that any would discard.

Readonly restricts a typed reference; freezing affects ordinary object properties at runtime. Structural typing checks shape; generics preserve type relationships; discriminated unions associate fields with a literal tag. Class instances combine state and behavior. None of these types validates external input.

Later applications: stacks for undo history, queues for matchmaking, graphs for game paths, WeakMap/WeakSet for lifetime-associated metadata, and typed arrays/Buffer for binary data. Add these when a project needs them.
