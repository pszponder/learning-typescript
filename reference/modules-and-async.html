Modules & asynchronous work

Keep reusable logic in modules; await values that arrive through promises.

// messages.ts
export type Turn = "again" | "finished";

export function nextTurn(lives: number): Turn {
  return lives > 0 ? "again" : "finished";
}

// main.ts (a separate file beside messages.ts)
import { nextTurn } from "./messages";
import type { Turn } from "./messages";

const turn: Turn = nextTurn(2);
console.log(turn);

Named imports use braces; default imports do not. Use import type for checking-only names. Nub supports these extensionless module paths. Modules handbook.

async function loadSecret(): Promise<number> {
  return 7;
}

async function main(): Promise<void> {
  console.log("before");
  const secret = await loadSecret();
  console.log(secret);
}

main().catch((error: unknown) => {
  console.error(error);
});
console.log("outside");

Async functions return promises. Await resumes with a fulfillment value or throws a rejection. Try/catch around awaited work handles that rejection; finally handles cleanup. Async does not offload CPU work. Promises.

Await inside for...of sequences work. Promise.all coordinates independent work concurrently, without canceling siblings when one rejects. forEach does not await its async callbacks.
