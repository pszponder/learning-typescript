Await a result

Your win: consume a promise and handle a failure without losing it.

A backend frequently waits for I/O. A Promise represents an eventual fulfillment value or rejection. An async function always returns a promise; await waits for its settlement within the async function, without blocking the JavaScript thread while waiting. Async does not turn CPU work into background work. Async functions.

async function loadSecret(): Promise<number> {
  return 7;
}

async function main(): Promise<void> {
  console.log("before");
  const secret = await loadSecret();
  console.log(secret);
}

main().catch((error: unknown) => {
  console.error(error);
});
console.log("outside");

The example uses a ready value to isolate ordering; it does not simulate real I/O latency. Unlike calling a Python async function, calling a JavaScript async function immediately starts its body, up to the first suspension. Await resumes later, even for an already fulfilled promise.

Worked example: follow the values

Read this as a separate small program. Predict its output before opening the explanation.

async function readPoints(fail: boolean): Promise<number> {
  if (fail) throw new Error("offline");
  return 4;
}
async function attempt(fail: boolean): Promise<void> {
  try {
    console.log("score", await readPoints(fail));
  } catch (error: unknown) {
    console.log(error instanceof Error ? error.message : "unknown");
  } finally {
    console.log("finished");
  }
}
async function demo(): Promise<void> {
  await attempt(false);
  await attempt(true);
}
demo().catch((error: unknown) => console.error(error));

  1. readPoints returns a Promise on both paths: fulfilled with 4 or rejected with an Error.
  2. await turns the rejection into a throw inside the try, so catch prints offline.
  3. finally runs once per attempt; awaiting attempts in order keeps the output sequential.

Handle rejected work

async function loadSecret(): Promise<number> {
  throw new Error("Secret unavailable");
}

async function main(): Promise<void> {
  try {
    const secret = await loadSecret();
    console.log(secret);
  } catch (error: unknown) {
    console.error(error instanceof Error ? error.message : "Unknown failure");
  } finally {
    console.log("attempt finished");
  }
}

main().catch((error: unknown) => console.error(error));

Throwing inside async rejects its promise. Await turns rejection into an exception you can catch. Finally runs after success or failure; reserve it for cleanup, and avoid returning from it. Calling a promise-returning function without await inside try does not catch a later rejection. Using promises.
