Set: unique player membership

Your win: Keep one membership entry per player ID.

A Set stores unique values in insertion order. Set<string> works well for lobby membership. add returns the set, has checks membership, delete removes a value, and size counts distinct values. Unlike an array, a Set has no numeric indexing.

// Membership is unique; repeated insertion does not add another copy.
const players = new Set<string>();
players.add("ada");
players.add("ada");
players.add("lin");
console.log(players.size, players.has("ada")); // 2, true
for (const id of players) {
  console.log(id);
}

Like Map keys, object values use identity: two separate { id: "ada" } objects do not deduplicate. Prefer a stable string ID when uniqueness means one player. A Set is not automatically an array in JSON; convert deliberately. Python sets are not ordered collections; do not transfer that assumption to JavaScript's insertion-order iteration.

add returns the original Set. Replacement is a deletion followed by addition. The union keeps first appearances. A separate snapshot survives clear, although copied object values would still share references.

Two Sets with equal contents are still different objects: a === b compares references. To compare membership, first compare sizes, then check that every value from one exists in the other. Set values that are objects also compare by identity. Use strings for player IDs. Set reference.
