Classes, instances, and this

Your win: Encapsulate a game counter behind methods.

A class defines how instances are constructed and which methods they share. new creates an instance; this refers to the receiver of a method call. A class is useful when state and behavior belong together. Plain records and functions remain useful for game rules.

class Counter {
  #value: number;
  constructor(initial: number) { this.#value = initial; }
  increment(): void { this.#value += 1; }
  current(): number { return this.#value; }
  static zero(): Counter { return new Counter(0); }
}
const counter = Counter.zero();
counter.increment();
console.log(counter.current()); // 1

#value is private at runtime. TypeScript’s private modifier mainly enforces access during checking. Static methods belong to the class, not an instance. A detached method loses its receiver; calling counter.current() keeps it, and an arrow callback such as () => counter.current() captures it. Prefer composition—passing a helper into a class—before introducing an inheritance hierarchy.

Worked example: follow the values

Read this as a separate small program. Predict its output before opening the explanation.

class Wallet {
  #coins: number;
  constructor(coins: number) { this.#coins = coins; }
  addCoin(): void { this.#coins += 1; }
  balance(): number { return this.#coins; }
}
const first = new Wallet(2);
const second = new Wallet(2);
first.addCoin();
const readFirst = () => first.balance();
console.log(readFirst(), second.balance());
Reveal the output and walkthrough
3 2
  1. Each new call allocates an instance with its own private field.
  2. first.addCoin uses first as the method receiver, changing only that instance.
  3. The arrow calls the method through first; it does not detach balance from its receiver.
