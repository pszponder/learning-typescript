Choose a value with a ternary

// Inside a function, these two versions choose the same value:
if (lives > 0) {
  return "again";
} else {
  return "finished";
}

// Ternary version:
return lives > 0 ? "again" : "finished";

Read condition ? whenTrue : whenFalse as “if the condition holds, choose the first value; otherwise choose the second.” A ternary is an expression, so it can follow return or an assignment; only the chosen branch is evaluated. MDN: conditional operator.

Python comparison: "again" if lives > 0 else "finished". JavaScript puts the condition first. Keep branches when they make multiple steps easier to read.

Choose how to write the function

type Turn = "again" | "finished";

// Function declaration
function nextTurn(lives: number): Turn {
  return lives > 0 ? "again" : "finished";
}

// Function expression assigned to a const
const nextTurnExpression = function (lives: number): Turn {
  return lives > 0 ? "again" : "finished";
};

// Arrow function with a block body
const nextTurnArrow = (lives: number): Turn => {
  return lives > 0 ? "again" : "finished";
};

// Arrow function with an expression body (implicit return)
const nextTurnShort = (lives: number): Turn =>
  lives > 0 ? "again" : "finished";

const declares a binding that cannot be reassigned; the expression on its right creates the function. The arrow separates parameters from the body. The return annotation : Turn goes before the arrow. These examples behave alike for this rule. TypeScript: function annotations.

Watch the braces. An expression body returns its value automatically. A block body needs an explicit return to return a value. Arrow functions use the surrounding this; unlike function declarations, these const functions cannot be called before initialization. We will revisit those distinctions when needed. MDN: arrow functions.
