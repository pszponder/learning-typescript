Interfaces and structural typing

Your win: Accept any object that supplies a game capability.

Optional later topic. Study this when a project needs it; it is not required before the main-path modules, async, or workflow lessons.

An interface describes a shape for the checker. Structural typing means a matching shape is sufficient without explicit inheritance or implements. Interfaces disappear at runtime; they cannot validate a request. A class can declare implements to check its instance shape, but that does not generate methods.

// The interface describes the required shape; implementation supplies behavior.
interface ScoreReader {
  current(): number;
}
function displayScore(reader: ScoreReader): string {
  return "Score: " + reader.current();
}
const fakeReader = { current: () => 4, label: "test" };
console.log(displayScore(fakeReader)); // Score: 4

Both interfaces and type aliases can describe object shapes. Interfaces can extend other interfaces; aliases also express unions and tuples. Fresh object literals receive excess-property checks, so accepting a variable with extra properties does not mean every inline literal is accepted. Choose a small capability contract rather than requiring an entire class when only one method is needed.

Worked example: follow the values

Read this as a separate small program. Predict its output before opening the explanation.

// The interface describes the required shape; implementation supplies behavior.
interface LabelSource { label(): string; }
function heading(source: LabelSource): string {
  return "Player: " + source.label();
}
const local = { label: () => "Ada", score: 3 };
console.log(heading(local));
Reveal the output and walkthrough
Player: Ada
  1. The consumer needs only a label method returning string.
  2. The variable local has an extra score field, but still meets the required shape.
  3. There is no inheritance or implements clause; the checker compares structure.
