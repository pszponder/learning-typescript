Objects: a named game state

Your win: Describe a player using named fields and a checked object shape.

Use an object for a record with named fields. It resembles a Python dictionary in syntax, but a TypeScript object type describes a shape with specific property names. Dot access reads a known property; bracket access can use a key expression.

type Player = {
  name: string;
  score: number;
  nickname?: string;
};
const player: Player = { name: "Ada", score: 0 };
player.score += 1;
console.log(player.name, player["score"]);
console.log(player.nickname ?? "anonymous");

The ? marks an optional property; reading it may yield undefined. The ?? operator supplies a fallback only for null or undefined, preserving values such as an empty string or zero. A type annotation checks code; it does not validate incoming JSON. Assigning an object shares its identity. Object spread creates a shallow copy; nested objects remain shared. readonly on a field prevents assignment through that type, not runtime mutation by every possible reference.

Read a computed key, update, add, and delete

type Member = { name: string; score: number; nickname?: string };
const member: Member = { name: "Ada", score: 0 };
const key: "name" | "nickname" = "name";
console.log(member[key]);
member.score = 2;
member.nickname = "Ace";
console.log(Object.hasOwn(member, "nickname"), member.nickname);
delete member.nickname;
console.log(Object.hasOwn(member, "nickname"), member.nickname);
console.log("toString" in member, Object.hasOwn(member, "toString"));
Check the result and trace
Ada
true Ace
false undefined
true false

Bracket access uses the key value. Adding nickname makes it an own property; delete removes it. toString is inherited from the normal object prototype, so in and hasOwn differ.

A value of undefined is not the same as an absent property: an own property can exist with that value. TypeScript optional-property rules also depend on exactOptionalPropertyTypes; delete expresses removal directly. hasOwn returns a boolean but does not automatically narrow every arbitrary key or optional value for the checker. Presence checks.

Enumerate and make a merged copy

const defaults = { music: true, volume: 3 };
const settings = { ...defaults, volume: 0 };
console.log(Object.keys(settings).join(","));
console.log(Object.values(settings).join(","));
for (const [key, value] of Object.entries(settings)) {
  console.log(key, value);
}
console.log(Object.keys(settings).length, defaults.volume);
const rebuilt = Object.fromEntries(Object.entries(settings));
console.log(rebuilt.volume);
Check the result and trace
music,volume
true,0
music true
volume 0
2 3
0

The later volume property overrides the copied default. Enumeration reads own enumerable string properties; iteration does not modify defaults. fromEntries constructs a new object but does not recover a precise domain type or validate its shape.

Return to enumeration after the destructuring and loops lessons. Object.keys returns string[]; do not assume every resulting string is automatically a key of a narrow TypeScript type. Object.entries is often simpler for value iteration. Object.entries reference.

A dictionary-shaped object

Record describes an object type, not another runtime container. A finite key union requires those named properties:

type Side = "red" | "blue";
const totals: Record<Side, number> = { red: 0, blue: 1 };
console.log(totals.red); // 0

For an open lookup, Record<string, number> describes numeric property values. Enable noUncheckedIndexedAccess so a missing dynamic entry includes undefined; use ?? 0 if zero is the intended fallback. For dynamic player IDs, the upcoming Map lesson provides explicit get, set, and has operations. Neither object typing nor Record validates incoming JSON. Record reference.

Optional practice: create scores for red and blue, then temporarily omit blue and read the diagnostic. This is object-shape practice, not a new collection to learn.

Follow-up: nested records and arrays of objects

Known shapes use nested object types. A team can contain settings and an array of players. Dynamic dictionaries can nest too: Record<string, Record<string, number>> describes an object lookup inside another object lookup. Neither level guarantees a particular dynamic key exists.

type Team = { settings: { limit: number }; players: { id: string; score: number }[] };
const team: Team = { settings: { limit: 3 }, players: [{ id: "ada", score: 0 }] };
const found = team.players.find(player => player.id === "ada");
if (found !== undefined) found.score += 1;
const shallow = { ...team };
shallow.settings.limit = 5;
console.log(team.players[0]?.score, team.settings.limit);
const totals: Record<string, Record<string, number>> = { red: { ada: 2 } };
console.log(totals["red"]?.["ada"], totals["blue"]?.["ada"] ?? 0);
const red = totals["red"];
if (red !== undefined) delete red["ada"];
console.log(totals["red"]?.["ada"]);
Expected output
1 5
2 0
undefined

find returns the existing player object; mutating it changes the object in the array. Object spread copies only the outer team, so settings remains shared. Optional chaining makes a read safe, but it neither creates missing parents nor supports assignment to an optional chain. To update without mutating team, create a new outer object and copy every nested level you change. A new players array alone still shares its player objects. For dynamic or user-supplied keys, prefer Map. Optional chaining · Object types.
