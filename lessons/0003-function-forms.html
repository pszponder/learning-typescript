Three ways to write a function

Your win: recognize function declarations, function expressions, and arrows while preserving a game rule.

// Compare return behavior: an arrow block needs an explicit return statement.
// Declaration
function addLife(lives: number): number {
  return lives + 1;
}

// Function expression assigned to a const
const addLifeExpression = function (lives: number): number {
  return lives + 1;
};

// Arrow with a block body
const addLifeArrow = (lives: number): number => {
  return lives + 1;
};

// Arrow with an expression body
const addLifeShort = (lives: number): number => lives + 1;

These examples have the same result. const declares a binding that cannot be reassigned; the expression to its right creates the function. In an arrow, the return annotation sits before =>. A block body needs return to return a value; an expression body returns automatically. Arrow function reference.

Function declarations can be called earlier in their scope. A const function must be initialized before use. Arrows capture surrounding this instead of getting their own this from the call; they also cannot be used as constructors. These differences matter later for object methods.

Worked example: follow the values

Read this as a separate small program. Predict its output before opening the explanation.

// Compare return behavior: an arrow block needs an explicit return statement.
function doubleDeclaration(points: number): number {
  return points * 2;
}
const doubleArrow = (points: number): number => points * 2;
const doubleBlock = (points: number): number => {
  return points * 2;
};
console.log(doubleDeclaration(4), doubleArrow(4), doubleBlock(4));
Reveal the output and walkthrough
8 8 8
  1. The parameter and return annotations describe numbers in all three forms.
  2. The expression-body arrow returns the multiplication without a return keyword.
  3. The block-body arrow requires an explicit return. Function form changes; the arithmetic does not.
