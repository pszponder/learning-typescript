A guess with three outcomes

Write the rule that a future game API will call. Your win: a function whose result can only be one of three allowed strings.

Read a small contract

type Turn = "again" | "finished";

function nextTurn(lives: number): Turn {
  if (lives > 0) {
    return "again";
  }
  return "finished";
}

function introduces the function; braces delimit its body. The parameter annotation follows lives; the return annotation follows ). Turn names a union of two string literals. Returning "done" would violate it. See the function and literal-type documentation.

Backend connection. A small explicit set of outcomes helps callers handle business rules. But annotations are erased: incoming HTTP data still needs runtime validation. Why types are not runtime guards.

function judgeGuess(guess: number, secret: number): GuessResult {

console.log(judgeGuess(3, 7));  // expected: "too-low"

Hint if you need it

Use an if branch for guess < secret, another for guess > secret, and return the remaining result after those branches.

Then deliberately return "winner" in one branch. Read the diagnostic and undo that change. Separately try calling judgeGuess("7", 7). Explain the error before removing that call.
