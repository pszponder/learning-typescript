Map: a dynamic score lookup

Your win: Track scores for player IDs that appear at runtime.

A Map stores key-value entries and preserves insertion order. Use an object for a known record shape and a Map for dynamic keys. Map accepts keys of any type; Map<string, number> restricts this lookup to string IDs and numeric scores. It is a useful counterpart to a Python dict.

// Distinguish a missing key from a stored value; updates can change existing entries.
const scores = new Map<string, number>();
scores.set("ada", 2);
scores.set("ada", 3); // replace this key
console.log(scores.get("ada")); // 3
console.log(scores.get("lin")); // undefined
for (const [id, score] of scores) {
  console.log(id, score);
}

get returns undefined for a missing key; use has when presence itself matters. size counts entries, delete removes one, clear removes all. Object keys are compared by identity: two separately created objects with equal fields are different keys. JSON.stringify does not automatically serialize Map entries; convert explicitly when designing an API.

Use get/set for entries. Bracket notation on a Map is ordinary object-property access, not an entry lookup. Object keys use identity; missing get results and values explicitly stored as undefined require has to distinguish them.

const scores = new Map<string, number>();
scores.set("ada", 0);
scores.set("lin", 3);
const id = "ada";
scores.set(id, (scores.get(id) ?? 0) + 1);

  2. get returns the stored zero; ?? preserves it before incrementing.
  3. has answers presence, while get for the missing zoe key returns undefined.

Follow-up: nested Maps and grouped members

Use Map<string, Map<string, number>> for dynamic team-to-player scores, or Map<string, Set<string>> for room membership. Each parent lookup can be missing. Initialize a missing child explicitly, then update it. These are compositions of Map and Set, not new primitive structures.

// Distinguish a missing key from a stored value; updates can change existing entries.
const teams = new Map<string, Map<string, number>>();
let red = teams.get("red");
if (red === undefined) {
  red = new Map<string, number>();
  teams.set("red", red);
}
red.set("ada", 2);
console.log(teams.get("red")?.get("ada"), teams.get("blue")?.get("ada"));
const outerCopy = new Map(teams);
outerCopy.get("red")?.set("ada", 5);
console.log(teams.get("red")?.get("ada"));
red.delete("ada");
console.log(teams.has("red"), red.size);
Expected output
2 undefined
5
true 0

A new outer Map still shares child Maps. Copy the child Map too when changing it independently. Removing the last child entry does not remove the parent; decide whether empty parents should remain. For a matrix use row arrays; for named fixed state use object fields; for changing IDs use Maps.
